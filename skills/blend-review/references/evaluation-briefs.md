# Evaluating the suite's decisions

Use fresh runs with the suite available and only the raw user brief/assets. Keep evaluation outputs and reports outside published skill folders. These briefs are maintained test inputs, not evidence that such tests have passed. Compare renders and working flows; merely mentioning a specialist is not success.

| Brief | Observable behavior to assess |
|---|---|
| Build a busy bike-repair queue with filters, assignment, and return to the same queue | Dense usable comparisons, retained context, a complete narrow flow; no compulsory hero, scroll scene, or mascot |
| Create a colorful museum weekend page for families, with supplied illustrations | Direction derived from that audience/art; clear practical information, readable type, coherent small moments rather than a generic luxury treatment |
| Present a precision object using these authorized photos; no video | Product scale and credible imagery, honest claims, selective motion; no crude replacement model just to use 3D |
| Make a local data-card illustration collect items and resolve a badge | Stable reading layer and hit area; readable sequence, interruption, focus/touch and quiet modes |
| Design a reading app with an original friendly companion that responds to saving a note | Original identity, actual event coupling, clear status text, bounded acting, no mascot required to navigate |
| Make an editorial site in Arabic using supplied copy and brand colors | Suitable font coverage/shaping, RTL and mixed-content handling, responsive hierarchy; no Latin tracking assumptions |
| Refine this authorized purple Inter dashboard; change only empty states | Preserve brand, density, copy outside scope and routes; no unrelated new type or animation system |
| Build a static artist portfolio using these images | Content-derived composition and crops, no forced motion or recurring demo layout |
| Build a live assembly story; no video or frame sequence | Real reversible visual transformation, composed intermediate states, complete fallback and compact mobile alternative |
| Audit this site, don't change files | Location-specific findings with evidence and proportional fixes; no mutations |

Run more than one open brief before claiming range. Compare information architecture, type roles, overall page silhouette, assets, palette, and movement. Cosmetic changes over an identical hero/card/footer structure are weak evidence of distinct direction. Conversely, related screens in the same brand should retain useful consistency.

For rigorous comparison, use the same briefs, assets, tools, model settings, and effort allowance for baseline and revised suite, ideally with multiple independent runs and blinded review. Record real strengths, defects, failures, and coverage. Do not average away a broken task with an attractive screenshot. State explicitly when only packaging, source review, or handcrafted examples were checked.
